## 〇、验证机制：14 天影子锁（先试后锁，不属于资金模型）

影子锁是**验证机制**，不是资金模型——它不随任何资金模型改版而淘汰：

- 注册后前 14 天不锁真钱：产品经用户授权脱敏读取流水，每天虚拟发放"影子日额度"并记录真实消费轨迹；
- 第 14 天生成**影子对比报告**："如果你真的锁了，你已经攒下 ¥X；你的冲动消费集中在第 Y 天、晚上 Z 点"；
- 用户被自己的真实数据说服，一键转入真实锁定。产品不劝人锁钱——它让人看见没锁的自己；
- 影子锁同时是**数据生产舱**：记录每一次"想花又忍住"的克制事件，为冷静期、日发档位等参数的回测冻结积累对照数据。

## 一、资金模型总览（一张图看懂）

```
月生活费到账（示例 1500 元）
        │
        ├──→ 余量池（总称 = 初始锁定 + 回滚累计）
        │       ├─ 初始锁定 300 元（档位自选，¥50 起步）── 日常不可动
        │       └─ 回滚累计（每月余量回滚进来）── 日常可提
        │
        └──→ 基础生活费池 1200 元
                 │
                 ├── 日常额度 900 元 = 每天发 30 元 × 30 天
                 ├── 刚需池 200 元（水电 / 教材 / 医疗类白名单）
                 └── 放纵日 100 元 + 0.5×上月回滚（每月 1 天，自由支配）
```

**模型的本质**：用户先锁一个档位（¥50 起步，示例 300 元），剩下的钱自己花——但花的方式被结构化了：每天一笔、刚需直通、每月一次放纵。锁得不多，但锁得稳；日发不小气，因为 30 块是算出来的。

## 二、到账拆分：锁定池 + 基础生活费池

1. **锁定池**：用户主动锁定的部分（示例 300 元）。锁定池的钱**不参与日常发放**，只进不出，是"未来的自己"的压舱石。
   - 锁多少：**档位制，不用比例**——档位阶梯定稿（**档位 = 用户主动选择的预算约束强度，不是系统评级**）：

| 档位 | 名称 | 锁定金额 | 日常管理特点 |
|---|---|---|---|
| L1 | 轻度 | ¥50 | 基本不干预 |
| L2 | 标准 | ¥100 | 轻度约束 |
| L3 | 稳健 | ¥150 | 标准预算管理 |
| L4 | 强化 | ¥200 | 更明显的延迟消费 |
| L5 | 深度 | ¥300 | 强约束、自律激励更明显 |

   - 注意：**锁定金额不是消费额度**——L5 不是"系统觉得你不配花钱"，而是用户自己说"我这个月愿意把 300 块先锁起来"。钱是用户自己的，规则是用户自己选的；
   - **档位判定两道门槛（判定树，规则引擎直接翻译）**：

```
用户选择档位 K
       ↓
门槛一：当前锁定池余额 ≥ 该档位解锁要求？（基础档无门槛；全档位需 K_current ≥ 500）
       ↓ 是 / 否 → 拒绝并提示
门槛二：本月预算 M − K 是否满足基础生活保障线？（(M−K) ÷ D ≥ S_school）
       ↓ 是 / 否 → 拒绝并提示
计算基础生活费池 B = M − K
       ↓
日常池 + 刚需池 + 放纵日
       ↓
规则引擎执行
```

   - **解锁门槛用"当前余额"而非"历史累计"**：锁定池当前余额 ≥ 500 元才开放全部档位——如果曾经攒到 500 又全部退出、只剩 50，却永久保有 300 档，保障线机制就被绕开了。引擎检查的是 K_current，不是 K_history；
   - **基础生活保障线**（内部俗称"吃饱线"）：学校/地区检测的最低日生活线 S_school，首次使用以"即俗称的吃饱线，确保用户选择锁定档位后仍保有基本生活支出能力"口径解释。放 1200 进来想选 500/700 档的，剩余低于生存线——系统直接拒绝。**e日金可以帮助用户省钱，但不能通过省钱机制伤害用户正常生活**；
   - 锁定池的增厚只有一条路：**余量回滚**（见第四节）——系统不多给一分钱，锁定池长大是因为用户自己少花了；
   - 锁定池的取出走退出通道（随时可退、全额到账），锁定期内不动。
2. **基础生活费池**：剩下的 1200 元，拆三份：
   - **日常额度 900**：每天发 30 元，30 天正好 900；
   - **刚需池 200**：白名单类目（水电燃气、教材、医疗药品、考试报名）直接放行，从刚需池扣，不碰日常额度、不破锁定；
   - **放纵日 100**：每月 1 天不限日常额度，硬上限 = 放纵日余额 + 余量池，不可透支。

> 账目闭合检验：300 + 900 + 200 + 100 = 1500 ✓ 一分不多、一分不少。

## 三、每日发放：30 元的依据（答辩弹药）

**日发 30 元不是拍脑袋，是食堂账本算出来的：**

| 项目 | 金额 |
|---|---|
| 一顿正餐（饭 1 + 素菜 2 + 肉菜 4） | 7 元 |
| 两顿正餐 | 14 元 |
| 早餐 | 3-5 元 |
| 图书馆/自习咖啡（隔天） | 均摊 3 元 |
| **日生存底线** | **20 元** |
| **日正常标准（加瓶水、加顿加餐）** | **30 元** |

- 外地学生 30 天在校：20 元低标 = 月 600 元，30 元标准 = 月 900 元——**900 正好是日常额度池的总量**；
- 日发低于 20 = 产品逼用户饿肚子，违背"不误伤生活"红线；日发 30 = 有约束但不寒酸；
- 评委问"为什么是 30 块"，直接背这张表——这不是假设，是目标用户每天的账单。

**发放机制**（沿用）：每天固定时间，规则引擎把"可支付额度"上调 30 元——额度闸门打开，钱原地不动；仅当活期余额不足时，才触发用户授权的货基快速赎回补足。产品三不原则：不托管、不代持、不经手。

## 四、余量机制（本模型的核心新增）：花剩的钱，用户说了算

一天的 30 元没花完（比如饭 20 + 水 3，剩 7）：

```
当日额度 30 元
     │
   实际消费 23 元
     │
   余量 7 元 ──┬──→ 选项 A：自己留着（滚入下一天的可花额度，累积发放）
              │
              └──→ 选项 B：回滚余量池（并入锁定池，锁定 300 → 307）
```

1. **二选一，默认回滚**——默认设置是回滚（绿碳兑换机制需要池子越大越好，没用完的钱默认进池子）；用户可随时改选"留着"（累积到下一天），设置入口常驻；
2. 选项 B 的哲学：**锁定池从 300 涨到 386，是用户自己攒出来的，不是系统多给的**——一个月省 86 块，锁定池就厚 86 块（其中一半下月变成放纵加码，见第五节）。产品没多给钱，用户自己少花的钱被沉淀下来；
3. 选项 A 保证"钱是自己的、怎么留自己定"——余量永远没有"没收"属性；
4. 余量池可随时取用（一键转回可用），只进不出的是"锁定池"，余量池本身是活水；
5. **绿碳规则——两套独立账本**：资金账本和权益账本完全分开——只要形成有效余量，绿碳权益照常累计（G_{t+1} = G_t + g(R_t)），不因回滚而减少，权益也不是从本金里扣出来的。用户不会觉得"省下的钱拿去换权益、权益又把钱抵掉了"——真实体验是：**我少花了钱 → 钱还在我的账户体系里 → 同时获得绿碳权益**。

> 与 v2.0 旧版"余粮池生息"的差异：余量不再只"生息躺平"，而是给用户一个"加厚锁定"的选择——生息保留为余量池的默认收益形态，回滚是用户主动操作的增强路径。

## 五、刚需池与放纵日

1. **刚需池 200 元**：
   - 白名单类目（类目无歧义原则）：水电燃气、医疗药品、学校教材、考试报名；
   - 命中即放行：从刚需池扣，不碰日常额度、不破锁定、不用申请；
   - 有歧义类目（电脑/手机/交通）不进白名单，走紧急通道；
   - 刚需池月底没花完 → 并入余量池（用户可选回滚锁定）。
2. **放纵日 100 元（+ 天才加码机制）**：
   - 每月 1 天，用户自定日期；
   - 当天不限日常 30 元额度，硬上限 = 放纵日余额 + 余量池，不可透支、不可借；
   - **放纵加码公式：W = 100 + 0.5 × R₋₁**（R₋₁ = 上月余量回滚总额）——上个月没花完回滚的钱，**一半留在锁定池，一半自动并入本月放纵日**。省下的钱即时兑现成自由：这个月省 86，下个月放纵日就有 143；
   - 由此用户多了一条"不用走紧急通道也拿得到钱"的路——放纵日就是为"我上个月努力了"准备的正当出口；
   - 产品含义：**日常有约束，但预留合法自由空间**——用户不需要因为一次大额消费破坏整个计划。

## 六、AI 服务分层（三阶段 + Freemium）

**AI 铁律（不可违背）**：AI 永远只给意见与报告，做不做是顾客的事；**建议一定不涉及物理世界**——AI 无法预知一条建议在物理世界落地后会产生什么后果，所以所有输出克制、保守。AI 输出的是"消费行为报告"（事实），不是"建议"（方向）。资金动作由规则引擎按用户确认的规则执行。

**AI 永远只建议不裁决**——这条不因订阅改变。订阅改变的是"AI 帮你想多少"。

```
阶段一 · 默认观察（前 3 个月，免费）
    AI 读流水、学行为、出影子报告，只观察不介入
        │
        ▼ 3 个月后，二选一
┌──────────────────────────────┬──────────────────────────────┐
│ 订阅 AI 深度服务 ¥24/年       │ 不订阅（免费）                 │
│ ≈ 2 元/月，AI 介入管理：      │ 规则引擎自动发放 + 自主调档    │
│ 个性化额度建议、消费结构诊断、 │ 核心功能一个不少：锁定、日发、  │
│ 最大限度省钱的方案            │ 余量回滚、刚需、放纵日          │
└──────────────────────────────┴──────────────────────────────┘
        │                              │
        ▼                              ▼
    绿碳积分兑换通道（两侧通用）：自律攒积分 → 兑换 AI 服务时长
```

1. **免费层的底线**：不订阅的用户永远能用完整核心功能——规则引擎照常自动判定发放，用户自主调档位。产品不会把"省钱"锁在付费墙后面；
2. **订阅层的定位**：¥24/年 ≈ 每月 2 元，大学生一杯奶茶钱——AI 深度介入"如何最大限度省钱"（个性化额度规划、消费结构诊断、省钱方案），是增值不是必需；
3. **积分兑换**：不想花钱的用户用自律行为攒绿碳积分兑换 AI 服务——自律的人永远有路走，这正是"AI 听用户的话"的延伸；
4. **与自律评分的关系**：订阅/兑换决定"AI 帮多少"，自律评分决定"发放方式多自由"（周发/绿碳加速/证据档）——两条线独立，都通向"越自律越自由"。

## 七、自律体系：评分只决定权益，不决定本金（沿用 v2.0，联动点更新）

**四个角色的职责分工（写死，防止再混）：**

| 角色 | 决定什么 |
|---|---|
| **档位**（用户自选） | 我怎么管自己的钱（锁多少） |
| **自律评分**（系统计算） | 我因为坚持规则获得什么权益 |
| **规则引擎** | 今天具体发多少 |
| **AI** | 怎么帮我进一步省 |

**原则钉死（写进引擎的第一行）**：**自律评分评价的不是"你花得少不少"，而是"你执行自己制定的预算规则稳定不稳定"**——否则富裕的人天然高分、生活费低的人天然低分，体系会做歪。

**五维结构（v0.2 数学化版，权重待 MVP 回测冻结）**：

| 维度 | 权重 | 核心判断 | 公式（v0.2 草案） |
|---|---|---|---|
| 预算执行度 B | 30% | 有没有按自己选的档位执行 | B = 100 − 100×(V/T)；V=违规行为次数、T=有效管理天数；分段：正常 90-100 / 轻微偏离 75-89 / 多次偏离 60-74 / 频繁突破 <60 |
| 余量管理度 R | 25% | 有没有形成并合理处理余量 | R = 0.6R₁ + 0.4R₂；R₁=余量形成率、R₂=按规则处理率。**保护：余量不是越多越好**——不因"没有余量"判不自律，防为刷分不吃饭 |
| 冲动消费控制 I | 20% | 是否频繁短时间反悔式消费 | I = 100 − 20E − 10F，封底 0；E=异常冲动事件比例、F=频繁反悔/规则突破。**冷静后依然买 ≠ 不自律** |
| 连续稳定度 C | 15% | 持续执行而非三天打鱼 | C = 40 + 60×(1−e^(−d/30))；d=连续有效执行天数——前期增长快、后期平缓，防"100 天得 50 天两倍"的线性奖赏 |
| 主动管理度 A | 10% | 主动调档/看分析/处理预算 | 加分项不是强制任务——**不能为了刷分逼用户天天打开 App** |

**总分公式：S = 0.30B + 0.25R + 0.20I + 0.15C + 0.10A**（S 是自律评分，不是资金余额，也不是信用分）。

**评分保护机制（硬规则）**：
1. 刚需白名单消费 → 不进冲动评分；
2. 紧急通道释放 → 不扣自律分；
3. 合理使用余量 → 不扣分；
4. 用户主动退出 → 不因退出本身扣分——退出是绝对权利，不能嘴上说绝对权利、实际上用评分惩罚退出。

**慢进慢出**：加分按周结算、扣分按周计算；大幅变化需连续多次异常才触发（单次异常=观察、连续 3 次=轻度调整、连续 7 天异常=明显下降）。用户感觉不到"系统一直盯着我"，而是"系统在观察我的长期习惯"。

**一句话金句（答辩收口）**：**"e日金不评价用户有没有花钱，而评价用户能否持续执行自己制定的预算。"**

**评分不决定"能花多少钱"，只决定"花的方式有多自由"——三条权益线：**

1. **周发解锁**：自律等级达标（C 级以上 + 连续 6 周）→ 可申请周发（周一发全周额度）；当周破防 ≥2 次降回日发。周发是自律赚来的自由度；
2. **绿碳基金**：自律轨积分（每日不超支、白名单不外溢、按期储蓄）——等级越高，绿碳积分获取加速；
3. **紧急通道证据档**：等级越高，紧急直通的证据要求越宽松、自动放行额度越高（信任分级六域边界不变：只改流程复杂度，不改资金可得性，不碰征信）。

**调档纪律**（沿用）：升级慢、降级快（下调需连续 2 月达标、上调当月生效）；每次调档 = AI 建议 + 用户一键确认；评分不公开排名。

## 七点五、公式总表（用户与评委都查得到）

**账目层**（月为单位）：

| # | 公式 | 示例（M=1500） |
|---|---|---|
| 1 | 基础生活费池 B = M − L | 1200 = 1500 − 300 |
| 2 | 日常额度池 D = 30 × n（n=当月天数） | 900 = 30 × 30 |
| 3 | 刚需池 R = 200（示例档） | 200 |
| 4 | 放纵日 W = 100 + 0.5 × R₋₁ | 本月 100（首月）；上月省 86 → 本月 143 |
| 5 | 闭合检验：L + D + R + W₀ = M（W₀=放纵日基础 100） | 300+900+200+100 = 1500 ✓ |

**日常层**（天为单位）：

| # | 公式 | 说明 |
|---|---|---|
| 6 | 日发放 d = min(D ÷ n, 40)，**三段式：保障线 20 绝对下限 / 基准 30 / 上限 40** | 每天 8 点额度闸门；低于保障线则档位不成立；超出 40 的部分滚入计划目标池（防高预算被动回滚爆炸） |
| 7 | 日余量 rᵢ = d − cᵢ（cᵢ=当日消费） | 花剩多少 |
| 8 | 当日可用额度 A_t = d + C_t + X_t | d=基础日发；C_t=回滚累计中用户选择动用的部分（零摩擦提现）；X_t=特殊事件释放（白名单/紧急/放纵日） |
| 9 | 月回滚总额 R = Σ rᵢ（默认回滚，可改"留着"） | 省下的总额 |
| 10 | **月末结算顺序（先计提、后开放）**：I_{t+1} = 100 + 0.5R（加码先行计提进下月放纵日，日常不可提）；C_{t+1} = 0.5R（剩余进回滚累计，日常可提） | 防"用户放纵日前提光回滚、加码落空"的时间漏洞 |
| 11 | 锁定池累计 K_end = K_start + 0.5R | 净留存=回滚的一半（另一半已变放纵加码） |
| 12 | 绿碳权益 G_{t+1} = G_t + g(R)（独立账本） | **50/50 只是资金用途拆分，不是权益拆分**——200 块都是"本来能花但没花的预算"，权益 100% 照算，不因加码/回滚减少，也不从本金抵扣 |

| # | 公式 | 说明 |
|---|---|---|
| 13 | 自律分 S = 0.30B + 0.25R + 0.20I + 0.15C + 0.10A | 五维加权（v0.2 数学化草案，见 §七） |

## 七点七、规则引擎输入输出总表（代码翻译依据）

这张表定稿后，规则引擎 = 公式的直接翻译，不再"凭感觉写规则"：

| 输入 | 引擎计算 | 输出 |
|---|---|---|
| 月预算 M、档位 K | B = M − K | 锁定池、基础生活费池 |
| 基础生活池 B | B = D + E + I₀ | 日发池 / 刚需池 / 放纵日基础额度 |
| 当日消费 cᵢ | rᵢ = d − cᵢ；A_t = d + C_t + X_t | 当日可用额度、日余量 |
| 上月回滚 R₋₁ | 月末结算：I=100+0.5R₋₁ 计提；C=0.5R₋₁ | 放纵加码（锁定）+ 回滚累计（可提） |
| 自律评分 | 权益规则（60/70/80/90 阈值） | 周发/日发、绿碳加速、证据档 |
| 绿碳累计 G | 兑换规则 | AI 服务 / 支付权益 / 公益 |
| 紧急事件 | 紧急规则（默认放行） | 快速释放（锁定+回滚全动） |
| 用户调档 | 吃饱线校验 + 500 解锁门槛 | 新档位生效或拒绝 |

## 八、安全通道（沿用，一句话版）

- **紧急直通**：判不了也放行（默认放行 + 48 小时事后审计 + 信任分级）；
- **退出**：随时可退、全额到账、首退零成本——锁定池、生活费池、余量池，一分不少；
- **白名单**：刚需直通，不扣日常额度；
- **核心红线**：AI 只建议不裁决；规则引擎执行一切资金动作；所有阈值事前明示、用户确认。

## 八点五、分层合规设计（三类资金，三类监管）

产品业务触及三种不同性质的资金/产品，每一种对应不同的监管体系——方案按层显式映射，不在同一套口径里混：

| 产品层 | 业务形态 | 对应监管体系 | 我们的设计与口径 |
|---|---|---|---|
| **存款类** | 锁定资金在用户本人账户（活期 + 智能存款） | 银行存款监管：法定准备金、存款保险、账户管理 | 不归集资金、不改存款属性；准备金由负债属性统一计提，产品不产生额外监管成本（四不原则：不归集、不借贷、不诱导、不碰征信） |
| **固收类** | L0 货基 + L2 稳健层（货基/短债/固收+，R1-R2 代销） | 银行理财业务监管：资管新规、投资者适当性、销售行为管理 | 投教先行、适当性匹配、规则引擎筛选（不排序）、持牌代销渠道、话术层审计 |
| **权益类** | L3 进取层（指数定投 R3，仅路线图） | 银行与持牌子公司的业务衔接监管：独立法人、关联交易、风险隔离 | MVP 不开放；若开放需经持牌子公司衔接并单独合规评估，配占比上限与强化风险揭示 |

**答辩口径一句话**："我们把产品的每个资金层都映射到了对应的监管体系——存款归存款监管、固收归理财监管、权益走持牌子公司衔接。监管问题在我们的架构里是分层的，也是闭环的。"
