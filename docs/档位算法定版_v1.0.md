# e日金 v5.0 档位算法定版

> 版本：算法定版 v1.0 · 2026-09-12 · 项目负责人拍板
> 地位：v5.0 档位/锁定/回滚机制的唯一数学权威。**旧 v3.0 中与本文件冲突之处，以本文件为准。**
> 核心原则一句话：**先算"这个人最多安全能锁多少"，再决定他能进入哪个档位。**

**水库理论（2026-09-12 深夜项目负责人拍板，全文资金结构的全景隐喻）**：锁定池=最大的水库（所有没花掉的钱、回滚的钱最终都蓄入，可不断扩张）；回滚池=高位池塘（与水库链接，高位单向流向水库，容量有限 500 元，注定流向水库）；日常回滚与放纵日余额=两条小溪（注入池塘的活水）；绿碳基金=挑水浇田（挑水浇灌农作物=兑换绿色权益，水浇出价值而水库里的钱一分没少，绿碳是"用水行为"的权益记录不是水本身）。

**核心算法链（项目负责人定版 2026-09-12）**：

预算 → 保障 → 锁定 → 每日发放 → 消费 → 余量回滚

## 一、四个核心量（一切公式的挂载点）

| 符号 | 定义 |
|---|---|
| M | 用户本周期主动纳入 e日金 管理的预算总额 |
| D | 本周期剩余天数（动态，随周期推进减少） |
| S | 每日基本生活保障线（Demo 参数 20 元；正式产品 S=S_school/user，按校园消费环境、预算周期、用户历史消费数据参数化，待调研） |
| K | 锁定金额（当前锁定池余额） |

由以上四个量派生：

- **基本生活需求 G = D × S**
- **最大安全锁定额 K_max = M − D × S**（第一道闸门）
- **安全锁定率 Q = K / M**；**最大安全锁定率 Q_max = 1 − D×S/M**
- **约束资金规模 K_current = K_fixed + R_t**（锁定池=死水池逐步扩张 + 回滚池=荧光标记中转池满 500 转锁定；必要时经紧急/退出通道暴力引出）

---

## 二、第一道闸门：生活保障（硬约束，最高优先级）

**核心公式：K ≤ M − D × S**

- K_max ≤ 0 → **不可建立锁定**（预算连基本生活都不够，产品拒绝锁定并提示）
- **安全校验针对本周期新增锁定**：K_new ≤ K_max = M − D×S；历史已形成的固化锁定 K_fixed 不因新周期预算变化被追溯没收或强制转移，新周期预算不足则暂停新增锁定（终检钉死 2026-09-12）
- 产品哲学：**e日金 不是先决定"要锁多少钱"再逼用户适应；而是先计算保障线，再在安全余量内选择约束档位。**

## 三、第二层：标准档位 L1-L5（约束强度，不是系统评级）

| 档位 | 标准锁定额 | 定位 |
|---|---|---|
| L1 | ¥50 | 轻度约束 |
| L2 | ¥100 | 标准偏轻 |
| L3 | ¥150 | 标准约束 |
| L4 | ¥200 | 强化约束 |
| L5 | ¥300 | 深度约束 |

**两条铁律：**

1. **标准锁定额 ≠ 用户一定可锁**。可用性 = 档位金额 ≤ K_max。
2. **不截断规则**：档位金额超过 K_max 时，**不自动把用户截断成奇怪金额**（如 117.36 元），而是判定该档位不可用，提示选择更低档位或提高本周期预算。

## 四、第三层：500 状态门槛（产品状态门槛，非生存门槛，非首次锁定门槛）

> **500 元是完整档位/权益体系的状态门槛，不是"能不能开始锁钱"的门槛。**

| 状态 | 条件 | 含义 |
|---|---|---|
| 状态 A：基础约束状态 | K_current < 500 | 可使用基础约束能力（**开放 L1-L2 档**），不开放完整档位权益体系 |
| 状态 B：完整约束状态 | K_current ≥ 500 | 进入完整 L1-L5 档位体系及对应权益（周发/绿碳加速/证据档完整版） |

**档位集定版（项目负责人拍板 2026-09-12）**：基础约束状态=开放 L1（¥50）/L2（¥100）两档；完整约束状态=L1-L5 全档开放+完整权益体系。"低于 500 不能锁"是错误表述——低于 500 仍可锁定 L1-L2。**500 元不是基本生活保障门槛，而是完整约束体系的状态门槛；生活保障优先级永远高于 500 状态。**

**两个数（终检钉死 2026-09-12）**：①固化锁定额 K_fixed = K₀——真正日常不可动；②约束池余额 K_current = K_fixed + R_t——衡量当前累计形成的约束规模。**500 生命周期规则（终检补）**：首次达到 K_current≥500 获得完整约束状态，**在当前预算周期内保持**，不因单次合理提取即时降级；进入下一周期时重新安全校验——历史固化锁定不得突破新 K_max，新周期预算不足则暂停新增锁定，不追溯处罚已形成的合理回滚。

**500 必须服从生活保障**：K_current ≤ K_max 恒成立，500 状态永远排在生活保障之后。

## 五、档位判定树（完整流程）

```
用户输入本周期预算 M
        ↓
计算本周期剩余天数 D
        ↓
确定基本生活保障线 S
        ↓
Kmax = M − D×S
        ↓
  Kmax ≤ 0？
   ↓是              ↓否
不可建立锁定     进入档位判断
                   ↓
      逐档校验：L1=50 ≤ Kmax？
                   ↓
      再校验 L2=100、L3=150、L4=200、L5=300
                   ↓
      同时判断 500 状态（基础/完整）
                   ↓
      最终可用档位 = {档位金额 ≤ Kmax} ∩ {500 状态允许的档位集}
                   ↓
      用户确认 → 规则引擎执行 → 每日三段式发放（20/30/40）
                   ↓
      当日消费 → 未使用金额回滚 → 月末 50/50 分流
```

用户界面呈现："根据你的本周期预算和基本生活保障需求，当前最高可选档位为 L3（¥150）。"

## 五点半、每日发放公式（2026-09-12 校验修正，项目负责人定版）

- **普通日额度池**：B_normal = B − E − W₀（B=基础生活费池、E=刚需池、W₀=放纵日基础额度）
- **第一层·周期基准日额度**：d₀ = B_normal ÷ N；校验 20 ≤ d₀ ≤ 40（不满足则该档位/预算组合不成立）
- **第二层·每日实际可用额度**：d_i = min(d₀, B_remain − S×D_remain)；**计算时点**：B_remain=当日发放前剩余可支配预算，D_remain=含当日在内的剩余天数
- **40 元上限口径（终检钉死）**：40 是日常额度上限，不是"超出自动回滚"的触发线——回滚只来自消费后有效剩余 r_i = max(0, d_i−c_i)；消费需求超 40 走刚需白名单/紧急通道
- **系统不变量（终检钉死）**：正常状态下必须保证 B_remain ≥ S×D_remain + S（故 d_i ≥ S 恒成立）；不变量无法满足时不得继续压低日发，进入**预算保护状态**（暂停非必要新增约束/权益动作，提示用户调整预算配置）
- **放纵日**：d = W（替代当天日常额度，**非叠加**——叠加口径会重复计算当天日发，账目虚增）
- **示例账目（M=1500，K=300，B=1200）**：普通日额度池 870（29×30）+ 刚需池 230 + 放纵日 100 = 1200 ✓；D_daily = 1200−230−100 = 870，N=29 → d = min(870/29, 40) = 30 ✓，30 ≥ 20 ✓

## 六、回滚与 500 元缓冲边界（10 元缓冲机制）

**主线（2026-09-12 深夜项目负责人拍板，水池模型定版）**：日余量 r_i = d_i − c_i **荧光标记**入回滚池 R_t（高位水池：只进不出、笔笔可查）；**满 500 全额转入锁定池 K_fixed**（死水池：日常不可动、逐步扩张，必要时经紧急直通/退出通道暴力引出）；**超额缓冲**：X = R_t + r_i，X>500 时 Δ=X−500，Δ<10 全额发放、Δ≥10 发放 10 元且 Δ−10 并入明日预算金额。**R₋₁ 定义钉死**：上一周期内形成的有效回滚总额（行为统计量，不是资金余额）——用于放纵加码 W = 100 + 0.5R₋₁（额度公式，非资金划转）与绿碳权益（100% 照算，两套独立账本）。**放纵日余额**：放纵日额度未花完部分单独标记滚存，下月放纵日作为选项可提取 50%，其余 50% 不变。

**回滚 500 元缓冲边界 + 10 元缓冲机制（2026-09-12 深夜水池模型重定，余数留池修正）**：

X = R_t + r_i（R_t=当前回滚池余额，r_i=当日新增回滚）
- X ≤ 500：全部入回滚池
- X > 500：500 开闸放水进入锁定池，剩余 Δ = X − 500；Δ < 10 → 全额归用户持有；Δ ≥ 10 → 释放 10 元，**Δ−10 继续留在回滚池（下一阶段回滚起点）**

示例：498 + 7 = 505 → 释放 ¥5。498 + 22 = 520 → 释放 ¥10，剩余 ¥10 进入锁定池。

> 500 不是一道"卡死"的墙，而是一个有缓冲的状态边界。

## 七、示例计算（正文与附录 D 复用）

**例 1**：M=1500，D=30，S=20 → K_max = 1500 − 600 = 900 → L1-L5 五档全部可用 ✓

## 八、安全锁定率（风险监测指标，不决定档位）

Q = K / M；Q_max = 1 − D×S/M。

**用途定版（项目负责人拍板 2026-09-12）**：Q 只作为**风险监测指标/用户画像指标**，回答"这次锁定对我的整体预算压力有多大"——**不作为 L1-L5 档位的判定条件**。金额档位回答"我要给自己多强的约束"；锁定比例回答"这次锁定对我的整体预算压力有多大"。例：两个学生同样锁 300 元（一个 M=1500、一个 M=3000），Q 分别为 20% 和 10%，档位相同——比例若直接决定档位，同样的 300 元会产生不同档位，反而把产品变复杂。

## 十二、七条母规则（2026-09-12 终检定版，全文机制只从这里长出去）

① **安全先于约束**：K_new ≤ K_max = M − N×S − W₀（针对本周期新增锁定；历史固化不追溯没收）
② **档位是用户自选的约束强度**：50/100/150/200/300，不是系统判定"该不该花钱"
③ **500 是状态门槛不是生存门槛**：500=水库的水（K_fixed）——<500 开放 L1-L2；≥500 下一笔新资金自由选全档+绿碳加速；不凌驾 K_new≤K_max；不因单次资金动作实时掉档；历史 K_fixed 不参与新增锁定计算、不追溯解锁
④ **日发是预算分配不是资金划转**：B_normal=B−E−W₀；d₀=B_normal÷N；d_i=min(d₀, B_remain−S×D_remain)；钱在用户自己账户
⑤ **回滚是"用户省下的钱"**：荧光标记入回滚池（只进不出）→满 500 转锁定池（死水池逐步扩张可暴力引出）；超额缓冲回流；放纵日余额 50% 提取选项；资金与权益账本分离
⑥ **自律评分只决定"自由度"不决定本金**
⑦ **AI 只做镜子不做方向盘**：**规则引擎管钱，评分管权益，AI 管认知，用户管决定**

## 十二点五、母公式组（公式冻结基准，2026-09-12 终检定版）

**预算安全**：G = N×S + W₀；**K_max = M − N×S − W₀**（N=普通日数、W₀=放纵日基础 100；锁定后必须付得起普通日保障线+放纵日基础）；K_new ≤ K_max（安全校验针对本周期新增锁定；历史 K_fixed 不参与新增锁定计算、不追溯解锁）
**约束资金结构**：K_fixed = 锁定池（水库，可扩张）；R_t = 回滚池（池塘，满 500 开闸流入水库）。**两个 500 严格区分：回滚池 500 = 资金流转阈值（开闸水位线）；水库 500 = 用户状态解锁阈值（K_fixed≥500 下一笔新资金自由选全档+绿碳加速）——两者不是同一个数**；K_new ≤ K_max 永远优先；状态在当前周期内保持；历史 K_fixed 不参与新增锁定计算、不追溯解锁。**额度与资金分离**：放纵日加码 0.5R₋₁ 与余额提取 W_draw 均为"可使用额度"（消费权限），支付时从用户账户余额扣（含个人存款），不动回滚池/水库资金
**日额度**：B = M − K_new（锁定后剩余预算总额，含刚需）；**d₀ = 30（MVP 固定；20=保障线、40=突破标尺）**；E = B − N×d₀ − W₀（刚需池=专项余数，E<0 则组合不成立；普通日优先由公式链保证）；**B_daily = N×d₀ + W₀（日常预算账本，排除刚需池 E）**；d_i = min(d₀, B_daily_remain − S×(D_remain−1))（B_daily_remain=发放前、D_remain 含当日）；**公式管正常（B_daily_remain ≥ S×D_remain），不满足则不进公式、直接进预算保护状态（降档退钱重新规划→最低档不行全额退）**
**回滚**：r_i = max(0, d_i − c_i) 荧光标记入回滚池（只进不出）；X=R_t+r_i，X>500 时 500 开闸进锁定池、Δ=X−500：Δ<10 全额归用户、Δ≥10 释放 10 且 Δ−10 **留回滚池作下一阶段起点**；**绿碳汇率：锁定池 1:1、回滚池 1:0.8**（转池追溯规则待项目负责人拍板）
**放纵日**：**W = min(100 + 0.5R₋₁ + W_draw, 300)**（回滚加码自动+余额提取可选，300=基础100+增量顶额200）；当月使用上限 300；放纵日余额下月可提 50%、其余 50% 不变；顾客自设、每月一次、一次调整机会、普通日优先（公式链保证）
**自律评分**：Score = 0.30B + 0.25R + 0.20I + 0.15C + 0.10A（**符号纪律：S=保障线、Score=评分，两符号不混用**；B=max(0,100−100V/T)，T=0 时 B=100；**R₁=合理管理天数÷T（当日无突破且余量∈[0,0.5d_i]，正常花完与合理留余同等计分，过度节约与突破日不计入）；R₂=余量规则执行度（按规则处理天数÷形成余量天数，无余量时=100 防除零；默认回滚被遵守即满分，不逼用户天天操作）**；**I=max(0,100−20E−10F)，一般预算突破只进 B 的 V 不进 I（避免双重扣分）**）
