# e日金（e-rijin）

**青年账户预算管理服务 —— 把额度打开，让钱留在原地。**

> ⚠️ **声明**：本项目为第十七届"工行杯"全国大学生金融科技创新大赛的**学生参赛作品**，与工商银行（ICBC）**无任何官方关联**。代码为纯规则引擎演示（Demo），**不是生产系统**，不托管资金、不构成任何投资或理财建议。

## 这是什么

e日金 是一个面向青年客群的账户预算管理方案：不把钱转走，而是在原有账户余额上建立"可支付额度的规则闸门"。

核心机制：

- **档位锁定**：用户自选锁定档位（L1–L5），锁定后必须付得起每日保障线与放纵日基础（`K_max = M − N×S − W₀`）；
- **每日发放**：额度按安全截断公式发放，`d_i = min(d₀, B_daily_remain − S×(D_remain−1))`，预算不够时进入保护状态（退锁降档重新规划），绝不压低日发额度；
- **余量回滚**：当天没花完的额度"荧光标记"入回滚池，满 500 开闸转入锁定池（水库），超额部分按缓冲规则回流用户；
- **放纵日**：每周期末一天以 `W = min(100 + 0.5×R₋₁ + W_draw, 300)` 替代普通日发放——放纵日是替换，不是多发；
- **退出即时生效**：锁定资金 + 回滚池全额回到可支配，一分不少。钱始终在用户本人账户，产品不托管、不代持、不经手。

本项目未能晋级下一阶段评审，评审反馈为：**方案结构"头重脚轻"、缺少核心竞争力**。赛后复盘结论（摘要，详见 `docs/`）：

1. **换主语**：同样一套材料，把叙述主语从"大学生用户"换成"银行"（青年客群经营、睡眠户治理、负债端价值），产品的立论和壁垒才立得住；
2. **脚要重**：可验证的量化结果（公式法测算、试点指标、外部验证数据）比机制的精巧更能说服评审；
3. **砍头**：公式与机制设计服务于论证，不为复杂而复杂。

复盘是这份仓库最有价值的部分——**竞赛输了，但"诚实复盘 + 可运行代码"比奖状更值得公开**。

## 运行

```bash
pip install flask           # 仅 app.py 需要
cd flask-demo
python test_engine.py       # 先跑验收钉子
python app.py               # http://127.0.0.1:5000
```

Windows 下也可直接双击 `启动e日金.bat`（自动清理端口 → 起服务 → 打开浏览器）。

**编码注意**：Windows 默认 GBK 控制台直接运行 `test_engine.py` 会因测试名中的 `¥` 字符报 `UnicodeEncodeError`（非逻辑错误）。请使用：

```bash
PYTHONIOENCODING=utf-8 python test_engine.py
```

## 实现范围与未实现（如实标记）

**已实现**：预算设定、档位锁定（双校验 + 500 状态门槛）、每日发放（安全截断 + 预算保护状态）、余量回滚（荧光标记 + 500 开闸 + 超额缓冲）、放纵日（W 公式）、周期末结转、退出即时生效、事件账本。

**未实现（留插槽）**：自律评分、绿碳权益、刚需白名单、紧急直通、影子锁。上述功能在计划书中有完整设计，但 Demo 阶段未实现。

**不做**：本 Demo 不连接任何银行系统、不处理真实资金、不存储任何用户数据（全部状态存于内存，重启即清空）。
